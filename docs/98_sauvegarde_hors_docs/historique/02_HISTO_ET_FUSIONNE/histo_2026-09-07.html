ERREURS RESOLUES

PROBLEME : Zigbee tombe, OTBR instable, bouton Matter impossible a appairer.

CAUSE RACINE : la VM 100 (Home Assistant) capturait TROIS peripheriques USB
en passthrough par port physique :

  usb0: host=1-3    -> Sonoff Zigbee   <-- ERREUR, appartient a LXC 200
  usb1: host=1-4    -> ZBT-1 (Thread)  <-- correct
  usb2: host=1-5    -> BT Realtek      <-- ajoute par Eric en S1

Le dongle Zigbee etait vole a LXC 200 (Z2M). Un peripherique USB ne peut pas
etre partage entre une VM et un conteneur. HA n'a aucun besoin du dongle
Zigbee en direct : Z2M tourne dans LXC 200 et parle a HA via MQTT.

Consequences en cascade observees :
- /dev/serial/by-id/ absent de l'hote (les devices etaient sous usbfs)
- bind mount LXC 200 en "optional" -> echec silencieux, aucun message d'erreur
- dans le conteneur : /dev/ttyUSB0 = noeud mort
  "c--------- 0 nobody nogroup 188, 0" (permissions 000, inouvrable)
- numerotation ttyUSB qui s'inverse entre 1-3 et 1-4 selon l'ordre
  d'enumeration -> risque de piloter le mauvais dongle
- deconnexions USB correlees aux evenements tap100i0 (start/stop VM 100),
  et NON a une panne materielle comme suppose initialement

CORRECTION APPLIQUEE :
  qm stop 100
  qm set 100 --delete usb0
  qm start 100

RESULTAT VERIFIE :
  Port 003: Driver=cp210x    <- hote a recupere le Sonoff
  Port 004: Driver=usbfs     <- ZBT-1 toujours a la VM
  Port 005: Driver=usbfs     <- BT toujours a la VM
  /dev/serial/by-id/usb-Itead_Sonoff_Zigbee_3.0_USB_Dongle_Plus_V2_940fc42b
    f9c2ef11be72e6b08048b910-if00-port0 -> ../../ttyUSB1   [RECREE]

Note : le lien by-id pointe vers ttyUSB1 et non ttyUSB0 - confirmation que la
numerotation brute est instable et que le bind mount DOIT rester sur by-id.
