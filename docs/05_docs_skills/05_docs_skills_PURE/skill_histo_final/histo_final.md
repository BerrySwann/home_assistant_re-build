Lights (3 desk Hue Play). Reason for the order (test by Eric and Claude on 2026-10-11): as long as Hue Sync streams (`mode: streaming` on the Play), the Hue bridge ignores the `light.turn_off` sent by HA (HA shows `off`, the lamps stay on). So Hue Sync must be stopped first. Method chosen (Eric's decision of 2026-10-11, tested at 19:30): cut the Entertainment stream through the Hue bridge API, without killing the process. Test result: `stream.active` goes to `false` in under 2 s, the 3 Play go back to `mode: normal`, `binary_sensor.moniteur_pc` goes `off`, and the HueSync application, left open, did not restart the stream during the 27 s of observation. Full procedure: `docs/06_docs_technique/01_pont_hue_hacking/01_pont_hue_hacking.md`. The bridge API key is written in no file: it is in the Windows user environment variable `HUE_BRIDGE_KEY`. Never display it, never write it in a journal, a report or a file. Trace: `debut lumieres` / `fin lumieres`.

1. PowerShell on the PC: `$k=[Environment]::GetEnvironmentVariable('HUE_BRIDGE_KEY','User'); Invoke-RestMethod -Method Put -Uri "http://10.32.154.206/api/$k/groups/4" -Body '{"stream":{"active":false}}' -ContentType 'application/json'`. Expected answer: `{"success":{"/groups/4/stream/active":false}}`. Then read back `Invoke-RestMethod -Uri "http://10.32.154.206/api/$k/groups/4"`: `stream.active` must be `false` (display only `.stream`, never the URL nor `$k`).
